# iPad AI Chat 工具设计

## 目标

构建一个可安装到 iPad 主屏幕的个人 AI 聊天工具。第一版以 DeepSeek 和其他 OpenAI 兼容 API 为核心，用户可在自己的设备中配置 API、创建 AI 角色、保存对话和导出备份。

## 第一版范围

- PWA：Safari 打开后可“添加到主屏幕”，具备独立应用外观、离线应用壳和 iPad 横竖屏布局。
- 模型配置：保存多个兼容 OpenAI Chat Completions 的服务配置；预填 DeepSeek 选项；支持连接测试、模型名和生成参数。
- 聊天：流式输出、停止、重试、编辑后重发、复制、Markdown 和代码块显示。
- 对话：新建、重命名、置顶、搜索、删除、自动本地保存与 JSON 导入导出。
- 角色：头像、名称、简介、系统提示词、默认模型与快捷指令；内置常用角色。
- 表情：角色可以配置一组表情符号，用户能在输入区发送；消息数据模型保留贴纸与富媒体分段类型。
- 安全：没有账号、没有默认云端存储；API Key 仅存于本设备的 IndexedDB。界面明确提示不要在共享设备上保存密钥。

## 不在第一版交付的功能

- 远程或本地 MCP 服务的真实连接与调用。
- 跨设备同步、用户账户、协作与公开分享。
- 原生 iPad 应用商店打包。
- 自动生成图片、语音和文件知识库。

这些功能不会被写死：数据模型含有 `tool`、`sticker` 和 `image` 消息分段；聊天服务层与 UI 层分离；后续 MCP 只需要新增受权限控制的工具网关。

## 架构

前端采用 React、TypeScript 和 Vite，构建为静态 PWA。所有个人数据保存在 IndexedDB，使用 Dexie 作为数据库访问层。服务层将 DeepSeek 当作 OpenAI 兼容 API 处理，并以可替换的 `ChatProvider` 接口隔离网络请求。

```
iPad Safari / 主屏幕 PWA
  ├─ 聊天界面与角色界面
  ├─ ChatProvider（DeepSeek / OpenAI 兼容）
  ├─ IndexedDB（配置、角色、对话、消息）
  └─ 导入导出 JSON

未来：PWA ── 可选安全网关 ── 远程 MCP / 本地 MCP 中转
```

浏览器直接连接模式是默认模式。若目标服务不允许浏览器跨域访问，或用户需要将 API Key 留在服务器端，后续部署一个小型安全网关；它不保存聊天记录，并对 MCP 的写入型操作要求用户确认。

## iPad 体验

- 横屏：角色栏、对话栏、聊天内容三栏显示。
- 竖屏和分屏：侧栏收为抽屉，只保留聊天主区。
- 触摸目标不小于 44px；兼容安全区域与软键盘。
- 深色、浅色和跟随系统主题；支持较大字体。
- 离线时能阅读已有对话和编辑草稿；发送操作显示清晰错误提示。

## MCP、头像与表情的扩展边界

每条消息采用分段结构，而非只保存纯文本：`text`、`sticker`、`image`、`tool-call`、`tool-result`。角色记录包含头像和可选的表情集合。未来 MCP 工具统一经过权限层：只读工具可配置直接调用；涉及写入、删除、支付、发信或外部提交的工具必须单次确认，并在对话中留下调用记录。

PWA 无法直接运行电脑上的 stdio MCP 服务。因此将来本地 MCP 需要一台电脑上的中转程序，或使用远程 HTTP MCP 服务；这一限制会在 MCP 设置页中明确说明。

## 验收标准

1. 在 iPad Safari 中打开部署地址，能添加到主屏幕并以独立窗口启动。
2. 能输入 DeepSeek Key 与模型名，测试连接并流式获得回答。
3. 能创建带头像和提示词的角色，切换角色并保留对话。
4. 刷新或关闭后，对话、角色与配置仍在本机。
5. 能将全部个人数据导出 JSON，并在另一台设备导入恢复。
6. 横竖屏、深浅色模式与窄分屏下主聊天功能可用。
7. 无网络、错误 Key、限流或兼容性问题会给出中文说明，且不丢失已输入内容。

## iPad 交付方式

部署到一个 HTTPS 地址后，在 iPad Safari 访问该地址，点击分享按钮，选择“添加到主屏幕”。此后从主屏幕图标启动即可。每次发布更新后，重新打开应用会自动获取新版本；本机对话数据不随前端更新丢失。会同时提供一个可下载的离线备份文件流程，防止 iOS 清理网站数据造成损失。
