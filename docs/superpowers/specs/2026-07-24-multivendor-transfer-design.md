# 多厂商配置与无账号设备迁移设计

## 目标

将 Aurora Chat 从单一 DeepSeek 配置升级为面向个人与小范围朋友使用的多厂商 AI 聊天工具，并在不创建用户账号的前提下，实现包含 API Key、角色、对话和设置的安全跨设备迁移。

本轮覆盖：DeepSeek、Kimi（月之暗面）、MiMo（小米）、硅基流动、智谱 GLM 与千问（阿里云百炼）。所有预设均使用各厂商的 OpenAI Chat Completions 兼容地址；应用保留“自定义兼容服务”作为高级选项。

## 范围与边界

### 本轮交付

- 厂商选择器、推荐模型选择器和每家独立保存的本地配置。
- 根据厂商和模型自动填充 API 地址、推荐模型、温度提示与思考能力。
- 温度改为“严谨 / 平衡 / 创意”三档；模型固定或忽略温度时明确禁用并解释原因。
- 思考强度改为能力感知的“关闭 / 标准 / 深度”选择器；不支持强度档位的模型只显示实际支持的选项。
- 全量加密备份文件的导出与导入，包含 API 配置、角色、对话、消息和本地偏好。
- 以二维码和一次性传输码完成设备迁移：数据在发送端加密，服务端只接触密文，成功领取后不可再次下载，未领取时在 15 分钟后失效。
- 更新 README，将项目定位为跨平台个人 AI 工作台，说明支持厂商、迁移方式、隐私边界和 GitHub Pages 发布方式。

### 不在本轮交付

- 用户注册、长期云同步、多人共享或实时双向同步。
- MCP 的真实调用；仅在 README 和设置说明中保留后续接入边界。
- 图片、语音、文件消息和厂商的内置联网/工具调用。
- 任何明文 API Key、聊天内容或密码上传到传输服务。

## 设置体验

设置页依次展示：

1. **服务商**：选中厂商时自动切换到该厂商各自的本地配置，不覆盖其他厂商已保存的 Key。
2. **推荐模型**：每家提供少量经过官方文档核对的主流模型；“自定义模型”允许高级用户输入模型 ID。
3. **API 地址**：默认只读展示官方地址；“高级连接设置”中可改为自定义兼容地址。
4. **API Key**：唯一必须由用户填写的常规字段，按服务商分别保存在本机 IndexedDB。
5. **回答风格**：用严谨（`0.2`）、平衡（`0.7`）、创意（`1.0`）替代裸露的温度数字，并实时显示简短说明。
6. **思考强度**：关闭、标准、深度。适配层将其转换为厂商实际参数，或在模型仅支持开/关时隐藏无效档位并说明。

默认推荐值：

| 服务商 | OpenAI 兼容地址 | 推荐模型 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | `deepseek-v4-flash`、`deepseek-v4-pro` |
| Kimi | `https://api.moonshot.cn/v1` | `kimi-k2.6`、`kimi-k2-thinking` |
| MiMo | `https://api.xiaomimimo.com/v1` | `mimo-v2.5-pro`、`mimo-v2.5` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | 精选 DeepSeek、Qwen、GLM 模型；可自定义 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.2`、`glm-5` |
| 千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.7-plus`、`qwen3.6-flash`、`qwen3.7-max` |

预设使用厂商官方文档的当前模型名和地址；应用发布后如厂商更新模型，仅需更新内置目录，不迁移或改变用户已保存的自定义配置。

## 参数适配层

聊天层不直接读取界面文案，而接收规范化配置：厂商 ID、模型 ID、温度档位、思考档位。适配层生成各厂商的请求体。

- DeepSeek：`thinking.type` 和 `reasoning_effort`；标准对应 `high`，深度对应 `max`。
- Kimi：使用 `thinking.type` 开关；K2.5/K2.6 温度由模型固定为 `1.0`，界面提示而不传递用户温度。
- MiMo：使用 `thinking.type` 开关；思考开启时温度由模型固定，标准与深度不伪造差异。
- 硅基流动：支持时使用 `enable_thinking` 与 `thinking_budget`；按模型能力生成预算值。
- 智谱：使用 `thinking.type` 与支持模型的 `reasoning_effort`。
- 千问：使用 `enable_thinking`、`thinking_budget`，必要时使用 `reasoning_effort`。

流式解析同时识别 `delta.content` 与 `delta.reasoning_content`。本轮只保存和展示最终回答；保留协议字段和数据模型扩展点，后续可加入“显示思考过程”的受控开关。

## 数据与迁移

数据库从单一 `default` 配置升级为按厂商 ID 保存多个配置。旧版 `default` DeepSeek 配置在首次打开时自动转换为 `deepseek` 配置，不丢失 Key 或对话。

导出内容使用新备份版本，包含：

- 所有服务商配置和 API Key。
- 角色、角色提示词、头像和表情。
- 对话、消息、置顶状态和草稿。
- 应用偏好与备份版本信息。

### 加密备份文件

用户填写一个备份密码。应用通过 Web Crypto 生成 16 字节随机盐与 12 字节 IV，使用 PBKDF2-SHA-256（600,000 次迭代）派生 256 位 AES-GCM 密钥后加密完整 JSON。文件携带格式版本、盐、IV 与密文，不包含明文 Key 或对话。导入时必须输入同一密码。

为了保持旧文件可用，现有 JSON 备份仍可导入；新导出默认使用加密格式。导入前让用户选择“替换本机全部数据”或“合并并保留本机数据”。同 ID 冲突时以更新时间较新的记录为准。

### 一次性传输码

临时传输服务部署在独立 Cloudflare Worker 与 R2 存储中，与 GitHub Pages 前端分离。

1. 发送端生成全量快照、16 字节随机传输 ID、256 位随机传输密钥和 12 字节 IV，在本机 AES-GCM 加密。
2. 发送端通过 Turnstile 防滥用验证后上传密文；Worker 返回随机传输 ID。
3. 二维码使用普通 HTTPS 页面链接：`https://said1120.github.io/aurora-chat/?transfer=<id>#key=<base64url-key>`。传输 ID 位于查询参数，密钥仅位于 `#` 片段，因此不会发送给 GitHub Pages 或中转服务；服务器只有密文和 ID，无法解密。
4. 接收端扫码或手动输入传输码，下载并在本机解密、预览和确认导入。
5. 成功下载后 Worker 立即删除对象和元数据；未领取的数据在 15 分钟后拒绝访问并由清理任务删除。

初版限制单个迁移包为 20MB，并明确提示迁移过程中两台设备都需联网。若用户不愿使用临时服务，可始终选择加密文件备份。

## 安全与失败处理

- API Key 只以明文存在于当前设备运行时与本地 IndexedDB；传输服务永不获得明文。
- 不将 API Key 写入 GitHub、日志、错误上报或二维码可见文本。
- 传输服务对包大小、过期时间、单次下载与 Turnstile 验证设限，降低匿名上传滥用风险。
- 解密失败、网络中断、传输已领取或过期时，不修改接收端本地数据。
- 导入前显示迁移内容摘要及替换/合并选择，并提示先导出本机备份。
- 传输服务部署前要求项目所有者登录 Cloudflare；未获得该授权时，先交付加密文件迁移和厂商配置功能。

## 验收标准

1. 选择任何预设厂商后，地址、模型与说明正确切换，并可返回原厂商继续使用已保存 Key。
2. 旧版 DeepSeek 配置升级后仍可聊天。
3. 不同模型的温度和思考控件不会发送厂商不支持或明确会被忽略的参数。
4. 加密备份文件不含可读 API Key 或消息正文，正确密码可恢复完整数据，错误密码不能修改本机数据。
5. 临时传输包在接收端成功恢复所有配置、角色、对话与消息；一次下载后不能再次取得，15 分钟后无法领取。
6. README 在不强调单一设备的前提下，准确说明跨平台使用、预设服务商、数据迁移、部署和 MCP 限制。
